# Current Production Closure Backlog

This file is the tracked current backlog owner. Historical receipts remain in
the append-only [known-gaps history](../claude/known-gaps-stable.md), but that
ledger is not a current execution entry point.

## P0 — immutable candidate

- Finish combined H10 plus W4-09–W4-13 local verification and independent
  review, then freeze the exact path and digest manifest.
- Under separate Git authority, protect `main`, enable blocking checks and
  dependency alerts, and promote one exact-SHA image archive.

## P1 — restore-first operations

- Deploy the canonical backup runtime, create one fresh manifest-bound backup,
  pass isolated restore parity, and complete off-host/KMS host-loss recovery.
- Configure protected production dry-run and deployment environments before an
  exact provider-off deployment and bounded L3 soak.

## P2 — durable execution and monitoring

- Close concurrency, restart recovery, saturation, shutdown and durable-worker
  SLO decisions; deploy monitoring and prove firing/resolved notifications.
- Raise risk-weighted backend branch coverage and make coverage blocking.

## P3/P4 — controlled value and commercial release

- Run one fresh retry-zero Fast provider window only after repaired production
  budget binding, then expand S1–S5 one separately authorized scenario at a time.
- Complete legal/trusted-signing/platform validation, controlled publish and
  rollback, human delivery acceptance, active-post metrics, capacity drills and
  final owner sign-off.

Any restore failure, active High/Critical finding, ambiguous provider outcome,
tenant leak, budget breach or missing human authority blocks the next gate.
